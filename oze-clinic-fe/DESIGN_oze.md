\## Overview



OZE Dental is a clinic management and operations system. Staff handle patient data all day, so the interface is \*\*calm and certain\*\*: every screen answers "what is this, what state is it in, what can I do" without decoration.



The system serves two surfaces with one set of tokens:



1\. \*\*Public website\*\* (Homepage, Services, Doctors, About Us, Contact Us, Book Appointment, Sign In / Sign Up). Airy, 16-18px text, real photography, pill CTAs, soft shadows.

2\. \*\*Internal application\*\* (Patient portal; Receptionist, Doctor, Dental Imaging Technician and Clinic Manager workspaces). Dense, 14px text, tables, borders instead of shadows, 8px-radius buttons.



\*\*Key Characteristics:\*\*

\- \*\*One blue, used for action.\*\* `{colors.primary}` (#165CDD) marks what can be clicked or what is selected. Non-interactive emphasis uses `{colors.ink}` at weight 600, never blue.

\- \*\*Status is text plus color.\*\* A badge always says its state in words; color only reinforces it.

\- \*\*Two densities, one product.\*\* Public is airy, the app is dense.

\- \*\*Patient data is never deleted.\*\* No delete action exists for patient records, appointments, treatment plans, clinical records, documents, invoices or payments. Changes are status changes, new versions or addenda.

\- \*\*One primary button per area.\*\* No new hues, no gradients.



\## Colors



\### Brand

\- \*\*Primary\*\* (`{colors.primary}` — #165CDD): primary buttons, links, selected states, the public utility bar.

\- \*\*Primary Hover / Active\*\* (`{colors.primary-hover}`, `{colors.primary-active}`): darker steps for hover and press.

\- \*\*Primary Soft\*\* (`{colors.primary-soft}`): selected rows, active nav item, info badges.

\- \*\*Primary Softer\*\* (`{colors.primary-softer}`): table row hover, highlight wash.

\- \*\*On Primary\*\* (`{colors.on-primary}`): text on any primary fill.



\### Text

\- \*\*Ink\*\* (`{colors.ink}`): headings and values.

\- \*\*Body\*\* (`{colors.body}`): paragraphs and default cell text.

\- \*\*Muted\*\* (`{colors.muted}`): labels and metadata.

\- \*\*Placeholder\*\* (`{colors.placeholder}`): placeholders and disabled text only. Never for required information.



\### Surface and lines

\- \*\*Canvas\*\* (`{colors.canvas}` — white): cards, inputs, the public page.

\- \*\*Surface Tint\*\* (`{colors.surface-tint}`): app background behind cards, table headers, alternating public sections.

\- \*\*Surface Muted\*\* (`{colors.surface-muted}`): read-only and disabled fields.

\- \*\*Surface Navy\*\* (`{colors.surface-navy}`): public footer and toasts only.

\- \*\*Border\*\* (`{colors.border}`): cards and dividers. \*\*Border Strong\*\* (`{colors.border-strong}`): inputs.



\### Semantic

Each meaning has a text token, a `-solid` token (dots, icons) and a `-soft` background: `success`, `warning`, `danger`. `info` aliases `primary`; `neutral` aliases `body`. `{colors.rating}` is for review stars on the public site only.



\### Status mapping

Map every status value from the SRS to a group by meaning.



| Group | Statuses that mean |

|---|---|

| Success | done, confirmed, paid, approved, verified |

| Info | active or in progress, checked in, called |

| Warning | waiting, early or late, pending a decision, partially done |

| Danger | cancelled, no-show, rejected, failed |

| Neutral | draft, not started, inactive |



Check-in arrival status (agreed so far, may change): On time = Success, Early = Info, Late = Warning, No-show = Danger, Cancelled = Danger. The three queue types (General Examination, Diagnostic Imaging, Treatment) use `{component.chip-queue}`: a neutral chip with an icon, not a semantic color.

\## Components



\### Buttons

\- \*\*`button-primary`\*\*: `{colors.primary}` fill, white text, 40px high, `{rounded.md}`. Hover `{colors.primary-hover}`, press `{colors.primary-active}`, disabled uses `{colors.surface-muted}` with `{colors.placeholder}` text. One per area.

\- \*\*`button-secondary`\*\*: white fill, `{colors.ink}` text, 1px `{colors.border-strong}` outline.

\- \*\*`button-cta-public`\*\*: pill-shaped, public site only.

\- \*\*`button-text-link`\*\*: inline text button in `{colors.primary}`.

\- Button labels are verbs that say what happens ("Check in", "Register").



\### Inputs \& Forms

\- \*\*`text-input`\*\*: white, 1px `{colors.border-strong}`, 40px high, `{rounded.md}`. Focus adds `{shadows.focus}`.

\- \*\*`text-input-readonly`\*\*: `{colors.surface-muted}` background.

\- \*\*`text-input-error`\*\*: error border in `{colors.danger-solid}` plus `{shadows.focus-danger}`, with the message from the SRS below the field.

\- Every input has a \*\*visible label\*\*. Placeholder is never the label.



\### StatusBadge

`badge-success`, `badge-info`, `badge-warning`, `badge-danger`, `badge-neutral`. Pill, `{typography.caption}`, always contains the status in words. Choose the group from the status mapping table.



\### Card

\- \*\*`card-app`\*\*: white, 1px `{colors.border}`, `{rounded.lg}`, no shadow.

\- \*\*`card-public`\*\*: white, `{rounded.xl}`, `{shadows.md}`.



\### Table

`{component.table}` has a `{colors.surface-tint}` header (`{typography.label}`, `{colors.muted}`), 1px row dividers, and `{colors.primary-softer}` row hover. The primary cell (name, ID) uses `{typography.title}`. Numeric columns use tabular numbers.



\### AppShell

Sidebar + top bar + content on `{colors.surface-tint}`. The active nav item uses `{component.sidebar-item-active}`. Below 1024px the sidebar becomes a drawer.



\### Modal

White, `{rounded.xl}`, `{shadows.lg}`, title in `{typography.heading-3}`. Actions that need a reason (changing queue order or room, refund or adjustment request) open a modal with a \*\*required Reason field\*\*.



\### Feedback

\- \*\*Toast\*\*: `{colors.surface-navy}` background, white text, `{shadows.lg}`. Confirmation reuses the button verb: Check in → "Patient checked in".

\- \*\*Inline alerts and empty states\*\*: use text from the SRS System Messages table (MSGxx). An empty list uses MSG02.



\### QueueColumn

A column of queue entries grouped by queue type. Each entry shows the queue number (tabular), patient name, a status badge, and the `{component.chip-queue}` for its queue type.



\### PublicHeader

`{component.utility-bar}` (40px, primary) above `{component.public-nav}` (72px, white). Wordmark left, menu center, "Sign in" text link and "Book appointment" `{component.button-cta-public}` right.



\## Content



\- Dates `dd/MM/yyyy`, time 24-hour `HH:mm`, currency `1.250.000 ₫`, phone numbers grouped `0912 345 678`, IDs exactly as stored.

\- Error, empty and confirmation texts come from the SRS System Messages table (MSGxx).

\- Vietnamese diacritics must render correctly in every font and weight used.



\## Do's and Don'ts



\### Do

\- Use `{colors.primary}` only for actions and selected states.

\- Pair every status color with a word.

\- Use borders, not shadows, for app cards.

\- Use `{rounded.pill}` only on the public site, badges, chips and avatars.

\- Show `{shadows.focus}` on every focusable element.

\- Use `space-\*` tokens for all spacing.



\### Don't

\- Don't add a delete action for patient records, appointments, treatment plans, clinical records, documents, invoices or payments.

\- Don't use blue for non-interactive emphasis.

\- Don't introduce new hues or gradients.

\- Don't use all-caps labels.

\- Don't put pill buttons inside the app.

\- Don't use images in staff workspaces (avatars and patient documents excepted).

\- Don't use any icon set other than `lucide-react`.

\- Don't use a heading with two colors (except the single homepage hero phrase).



\## Responsive Behavior



\### Breakpoints

Tailwind defaults.



| Name | Width | Key Changes |

|---|---|---|

| Mobile | < 768px | Public nav collapses to hamburger; hero stacks; Patient portal is mobile first; targets 44x44px |

| Tablet | 768–1024px | Public sections use `space-16`; sidebar is a drawer below 1024px |

| Desktop | ≥ 1024px | Full sidebar; staff workspaces designed at 1440px |

| Staff minimum | 1280px | Staff workspaces must work at 1280px |



\### Touch Targets

Minimum 40x40px in the app, 44x44px on mobile.



\### Motion

Limited to modal and drawer open/close (200ms ease-out), toasts and skeleton shimmer. Respect `prefers-reduced-motion`.



\## Accessibility



\- Text meets 4.5:1 contrast against its background.

\- `{colors.placeholder}` is only for placeholders and disabled text.

\- Every input has a visible label.

\- Icon-only buttons have a tooltip and `aria-label`.

\- Status is never conveyed by color alone.



\## Iteration Guide



1\. Work on one component at a time and reference its YAML key (`{component.button-primary}`).

2\. Variants (`-hover`, `-active`, `-disabled`, `-error`, `-readonly`) are separate entries under `components:`.

3\. Use `{token.refs}` everywhere; never inline hex.

4\. Decide the surface first: public (airy, pill, shadow) or app (dense, 8px, border).

5\. When in doubt about emphasis, use `{colors.ink}` at weight 600, not blue.

6\. Map any new status to a semantic group before choosing a color.



\## Known Gaps



\- `style.md` defines only `primary` (#165CDD). All other hex values, font sizes, shadow values and layout widths in this file are \*\*proposed defaults\*\* and should be confirmed against the team's `DESIGN.md` and `components/bundle.css`.

\- No logo is defined; the wordmark is a placeholder.

\- The Check-in arrival status mapping may change.

\- Component previews and the Tailwind config are not included here.

\- Dark mode is not defined.
